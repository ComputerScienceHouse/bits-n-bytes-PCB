Jetson HAT PLAN:

Not enough UART, want more UART.
This can be done by doing UART through SPI / I2C, there can be an STM32 on the HAT
that translates the UART through the SPI or I2C lines.
  What does this do?
    Altas code remains the same, still communicates through UART
    STM32 handles the transfer from UART -> SPI or I2C
    Jetson has code that breaks the data down from SPI or I2C into whatever it needs.
  
  Why this over what is currently being done?
    Currently we are connecting two USB->UART peripherals to the Jetson.
    This is dumb, USB is like important, and can sooo much more than just one UART.
    Current solution is also ugly
    This steamlines everything into the HAT, looks more professional, and the code
    changes wouldn't be severe, just have the STM32 send the data in a nice format
    like JSON, and read from it, just like how the UART is doing it.
    A way more professional solution than the UART->USB


An STM32 can be used for this, but it would require writting Firmware and flashing to it.
  This has the benefit of being cheap, like $1-2 for the STM, but has the downside that we would need to code it.

There are specialty chips: https://jlcpcb.com/partdetail/NxpSemicon-SC16IS752IPW112/C515281
  That are designed for briding UART and I2C/SPI, but it costs more since they're a more niche usecase.:w

I am leaning towards spending the extra 3-4 freedom dabloons if it means less trouble later.
